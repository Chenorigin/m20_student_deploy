## 2. 最优先缺陷：把位置误差限幅误当成速度限制

实际运行版本的 `src/m20_student_sdk/plugin/student_policy_runner.hpp:162`，在 ONNX 成功后执行：

```cpp
value = std::clamp(value,
                  ro.joint_pos(j) - speed * .02f,
                  ro.joint_pos(j) + speed * .02f);
```

板端 `software_velocity_limits_sdk_rad_s` 的腿部值为 2.5，因此每周期目标只能偏离实测角度 ±0.05 rad。关键是基准为**本周期实测角度**，不是上周期下发目标：即使持续请求同一远目标，只要关节没有移动，目标就永远追不上去。这限制的是位置跟踪误差，也没有保证相邻目标变化率受限。

腿部 Kp=80，目标速度和前馈力矩为 0。按训练采用的 PD 公式，采样时刻相对这帧测量的比例项因此最多约 ±4 N·m。**这不是完整电机力矩上限**：采样间位置变化、反馈延迟和阻尼项仍有影响；没有把计算值冒充真实电机扭矩。

从与板端同哈希的源文件直接抽取原 C++ 动作映射循环并执行，得到：

| 受控反例 | 训练映射 | 实际部署映射 |
|---|---:|---:|
| 实测 hipy=-0.30、模型动作=1、默认=-0.30、scale=0.25 | 目标 -0.05 rad | 目标 -0.25 rad |
| 相对该测量的比例项 | +20 N·m | +4 N·m |
| 测量不变，连续再执行 100 次 | 同一目标 | 仍为 -0.25 rad，不会逐步追上 |
| 下一帧 previous action | 1 | 0.2 |

小误差正对照不被截断，证明探针并非无条件把所有输出判成错误。这里动作=1是刻意输入的离线反例，**不是宣称故障瞬间模型输出过这个值**。

故障日志第 1002 行，进入 RL 前的站姿四膝实测约为 `0.745, 0.752, -0.747, -0.779` rad，默认目标为 `0.6, 0.6, -0.6, -0.6`。以零策略动作作反事实输入，正常 Kp=80 映射的比例项幅值约为 11.6–14.32 N·m，部署端四膝全被压到约 4 N·m。此前站立分支 Kp=100、固定默认目标，对应比例项幅值约为 14.5–17.9 N·m。该比较支持“站立能撑住，切 RL 后支撑能力明显下降”的解释，但不替代同步实测力矩。

参照训练保存的 `params/env.yaml`：腿部使用 `DelayedPDActuator`、Kp=80、Kd=2，动作是默认位置加缩放动作；训练的关节速度参数不是这条每周期对测量中心夹紧的算法。参考 SDK 的 `m20_policy_runner.hpp:603–616` 同样直接完成动作缩放/偏置，不包含上述夹紧。

判定：**已证实部署行为偏离训练控制映射，是本轮新增、应优先处理的故障点。** 它在推理成功周期也生效，因此不能只修 HOLD 就宣称解决。

## 3. 地形拒绝触发了不能可靠保持站姿的 HOLD

完整日志有 4 次进入 `rl_control`；记录地形覆盖拒绝 23 次、时间对齐拒绝 8 次、实测位置越界 3 次。第一段 RL 先出现地形拒绝，随后关节姿态明显变化，再出现越界。日志限频且没有逐周期统一时间戳，**这些数是打印次数，不能计算失败周期比例或准确对齐 3 秒**。越界也可能是失稳结果。

`student_policy_runner.hpp:66–71` 每次 HOLD 都把目标设为最新 `ro.joint_pos`，目标速度/前馈为零，调用 `reset()` 清空历史和上一动作。精确抽取函数复跑：实测从 -0.30 变为 -0.40，HOLD 目标也从 -0.30 变为 -0.40；旧站姿没有保留。姿态下沉时恢复参照跟着下沉，不能据“HOLD”这个名字认为它在保持站姿。

地形拒绝并非仅靠日志猜测：此前真实站姿预检收到 387 个地形消息，但错误明确包含 `Insufficient valid terrain coverage` 和 `Terrain/query pose stale or from future`。有消息不代表策略使用时合格。板端的对齐门槛为 60 ms、最少有效格比例为 15%。

额外对保存的 100 帧预试运行地形做敏感性检查：仅检查年龄/覆盖时，接收时 99 帧合格；人为增加 20 ms 等待后变为 86 帧。这只是说明接收时通过不能替代消费时通过，**不是实测 RL 成功率**，该窗口也不是倒地瞬间。

修正方向：先定义并验证短暂缺测、持续输入故障、姿态异常各自的安全退出/保持行为；固定目标也必须经过姿态、支撑和力矩验证，不能直接在线把 HOLD 改成某个默认姿态后让狗重试。同步恢复连续历史与真实 episode reset 的区别。

## 4. 还有上一动作输入语义不一致

部署端在夹紧后使用 `(value-baseline)/scale` 写入 `previous_`；训练 `observations.actions` 调用 `isaaclab.envs.mdp.observations:last_action`，返回 `env.action_manager.action`，是动作管理器收到的归一化动作，不是目标夹紧后的反算值。参考 SDK 也在物理目标缩放前保存原动作。

因此发生软件夹紧时，下一帧本体观测的上一动作通道已经与训练不同；HOLD 又把它和三帧历史一起清零。离线反例已证实动作 1 变成反馈 0.2。该差异对本次模型输出的具体影响尚未量化，不能以此单独断言摔倒。

## 5. 尚未闭合的因果与后续顺序

最有证据的部署故障组合是：**成功推理时支撑目标被夹紧；地形失效时切到随测量漂移的 HOLD；输入历史与上一动作又被改变。** 这些问题足以要求先修部署端，再评估模型，无需先靠重训解释事故。

本轮没有取得倒地瞬间同步的模型原始动作、最终目标、实测关节/力矩、IMU、地形年龄/有效率和 HOLD 状态。此前网络频率记录不能补齐这些变量。AOS/GOS 当前 journal 保留的起点都已晚于试运行窗口，因此本轮查询 `No entries` **不能排除**当时的驱动、电源、授时或硬件异常。当前 PTP 样本正常也只能描述当前。

建议执行顺序：

1. 离线修正动作整形语义并验证静态支撑、目标变化率、训练动作契约；不能直接删保护或盲目调大限值。
2. 修正 HOLD/退出状态及历史维护，增加有界、带统一单调时钟的逐周期记录，至少覆盖上述缺失量。
3. 在不输出电机命令的条件下验证两板感知在策略消费时刻的可用性，再做有支撑的接管/回退验证。
4. 通过这些检查后才进行现场小速度闭环；本轮没有执行该步骤。

分类为本项目个案排障，未发现需要跨机器人批量改写的第二实例。没有改生产控制、门槛、模型、服务或现场凭据。

## 在线排查新增结论

最初把 Python 观察程序放到 AOS CPU3 时，接收和定时器同时出现长停顿。该记录不能直接证明网络故障。移到 CPU5 后，15 秒收到 750 帧、750 个消费周期质量校验均通过；独立 C++ 观察器在 DDS 发现完成后的 700 个消费周期也均通过，最大接收间隔约 28.55 ms。GOS 同期本机约 50 Hz。

因此，当前静止窗口没有复现持续传输中断；初始异常至少受到观察程序执行位置影响。尚未覆盖运动、策略并发负载和原倒地瞬间，不能据此排除所有通信故障。

初版 Python 探针出现配置准备时序、NumPy 数组判断及 JSON 标量序列化错误，修正后重新执行；这些失败记录保留，没有算成机器人故障或通过。C++ 探针首轮缺少 ROS 链接库，补齐后成功执行。

证据：[AOS CPU3](../evidence/control_fix_20261015/aos_terrain_timing_v3.json)、[GOS 对照](../evidence/control_fix_20261015/gos_terrain_timing_v3.json)、[AOS CPU5](../evidence/control_fix_20261015/aos_terrain_cpu5.json)、[C++ 交叉测量](../evidence/control_fix_20261015/aos_cpp_terrain.json)。这些是质量检查，不是完整控制准入；正式 SDK 启动另执行了严格 `--control` 预检。

## 手柄状态转换

首次 L1 无动作已定位：日志明确记录重连锁拒绝 L1，需要先单独 R2 重新使能。我最初给现场的步骤漏了 R2，已纠正。

从 `liedown_state` 按 R2 会先进入 `joint_damping`，约 3 秒后才回到 `idle_state`。阻尼期间的 L1 不会排队执行。要以最新状态日志确认已到 Idle，再单独按 R2、松开、按 L1；R2 的使能窗口仅 5 秒。L2 仅在站立状态且本次 L1 后 30 秒窗口内接受。R1 是正常趴下；R2 是阻尼，不是站立保持，也不代替实体急停。

用户完成 R2→L1→L2→R1，并确认“已正常趴稳；接管时无明显异常”。SDK 状态依次为 `idle_state → standup_state → rl_control → liedown_state`，因此本轮确实进入了策略。逐周期记录共 452 行、约 9.02 秒，其中策略推理 17 帧、HOLD 435 帧。实际 RL 停留时间超过提示的 3 秒，下一轮仍限制短时观察。

- 第 17 号周期（进入约 0.3399 秒）触发 `terrain clock alignment`：地形年龄 60.8976 ms 超过既有 60 ms 门槛；没有放宽阈值。
- 本轮最大推理耗时 0.5396 ms；本体年龄最大 5.812 ms；相邻记录间隔 19.39–20.69 ms。支持定位为地形时效拒绝，不能单凭该字符串判断是系统时钟漂移。
- 首帧腿部目标与测量最大偏差约 0.2196 rad，实际膝力矩峰值约 23.58 N·m；已不再被旧的 ±0.05 rad 跟随测量限幅钳住。计划目标仍不是电机收包回执。
- 17 帧动作历史与上一帧归一化动作一致。进入 HOLD 后 435 帧目标全部等于最后一帧策略目标，轮速目标全部归零，未跟随测量重锚定；轨迹未丢行。
