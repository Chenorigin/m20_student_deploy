## 本地修复

旧 GOS `tick()` 将同步点云解码、输入打包、结果提交、地图查询和发布串在同一回调通道，位姿回调也不能同时推进。它还在耗时工作之前取得 `now`，后续用旧时间验证待发布帧。直接执行旧方法并注入 40 ms 打包阻塞后，实际已 70 ms 的帧仍按旧的 30 ms 年龄通过；无阻塞对照正常。注入证明代码缺陷，**不是实机打包耗时测量**。

- `ros_nodes.py` 将位姿接收、点云准备/后台任务、地形发布分成三个互斥回调组；GOS 实际入口使用三线程 executor，保留已有单进程估计 worker。
- 查询使用独立的位姿和地图 deque 快照，耗时计算在锁外。发布前重新检查实际时间、快照的接收 watchdog、session 和 worker 故障；保留原始查询位姿时间戳。
- 地图 generation 防止查询裁剪覆盖并发提交的新 patch；位姿重置后丢弃旧 session 的结果。后台 worker 非预期错误锁存并停止发布。
- `native_inputs.py` 将 IMU 转发与点云重建分组，实际入口使用两线程 executor。来源身份检查和输入故障锁存保留。
- 退出时先停 executor，再关闭 worker 和节点；状态 JSON/诊断计算移到短锁之外，增加 DDS publish 耗时指标。

代码：[GOS/AOS 节点](../src/m20_heightmap/m20_heightmap/ros_nodes.py)、[原生输入](../src/m20_heightmap/m20_heightmap/native_inputs.py)。控制目标核心、HOLD 解除方式、外参和 CPU 绑核未调整；后续预算修改如下。
